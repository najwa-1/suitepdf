# SuitePDF

An Arabic / English, light / dark document studio for Android and the web. Files are processed on the device, without accounts, uploads, or paid APIs.

## Develop

Node.js 22+ and npm are required.

```sh
npm ci
npm run dev
npm test
npm run build
```

## Included tools

Merge PDF, extract/reorder pages with a page expression such as `3,1-2`, remove pages, rotate selected pages, convert JPEG/PNG images to PDF, add Latin-text watermarks, number pages, read PDFs with page navigation, reverse page order, edit Unicode document metadata, export pages as JPG in a ZIP archive, and compress scanned documents. Scan compression rasterizes pages and removes searchable text, forms, links, and annotations; output is not guaranteed to be smaller. Keep originals. Merge and image order follow the file list; use the arrow controls to reorder files. Blank page selection means all pages. Encrypted PDFs are rejected. Large documents are limited by device memory. Editing signed PDFs invalidates their existing signatures.

The interface supports Arabic RTL and English, persistent light/dark themes, keyboard navigation, and mobile through desktop layouts. Watermarks currently support Latin characters only. Arabic and English fonts are bundled locally. PDF processing does not need network access after application assets load.

## Android APK on GitHub

The native Capacitor Android project is checked in. Every push to `main` builds an installable APK under Actions → Build Android APK → Artifacts. Publishing a GitHub Release attaches `SuitePDF.apk` automatically. Pushing a `v*` tag creates a release with the APK if it does not exist. GitHub Actions must be enabled with workflow write permissions. No APK is generated by merely uploading files without a workflow run.

This starter workflow produces a **debug-signed APK**, suitable for installation and testing, not a production-signed Play Store release. CI debug keys may change between runs; uninstalling an older APK may be necessary and deletes its app data. Before production distribution, configure a persistent private signing key in GitHub Secrets, release signing, an application versioning policy, and Play Store requirements. Never commit a keystore or signing passwords. CI usage is subject to GitHub account quotas.

Local Android development requires Android SDK, JDK 21, and platform/build tools matching the checked-in Gradle configuration:

```sh
npm run android:sync
npx cap open android
```

## Scope

This is a working first version, not feature parity with iLovePDF. OCR, Office conversion, advanced lossless PDF compression, password encryption, digital signing, and advanced content editing are not implemented. No artificial success screens or paid-service placeholders are included.

## Visual direction

The interface takes visual cues from the supplied Flowstate, Reelmark, Kai Nomura, and Leon Vasari references: soft studio light, editorial spacing, tactile paper depth, and staggered reveals. Motion respects reduced-motion preferences; pointer depth is enabled only on devices with a fine pointer. All visuals are generated locally without remote videos, third-party branding, or WebGL dependencies.
